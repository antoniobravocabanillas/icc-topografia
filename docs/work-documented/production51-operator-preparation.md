# Production51 offline operator preparation

**Blocked; not production ready.** `scripts/prepare-platform-production51.mjs` prepares deterministic review JSON only. It performs local reads and hashing, writes only to stdout, and has no credential, network, provider, database or deployment dependency. It neither modifies the supplied evidence nor generates an executable release file.

```powershell
node scripts/prepare-platform-production51.mjs --review-json
node --test scripts/test-prepare-platform-production51.mjs
```

The generator pins the exact raw bytes of the supplied production ledger/delta, Prisma schema and all 51 migration sources, with individual hashes for the seven pending migrations. `pins.candidate` records the inspected source revision `1db7bf2e70363ae82b15bf8ad4f1b103af4ac135`; content pins, rather than a moving HEAD or a claim of a clean checkout, control assembly. The sources remain in the delta's exact order; the already-applied followup is excluded. CRLF/LF changes, refreshed readbacks, extra/missing migrations and altered rollback records fail closed. Refresh requires independent evidence review and a code change to pins, never a CLI override. The generator is deterministic for those bytes; it makes no freshness claim.

The review SQL removes only the four outer BEGIN/COMMIT pairs, preserving the DDL bodies and provenance's 5-second lock / 30-second statement limits. A lexical splitter ignores quoted bodies and nested comments and rejects unexpected top-level control statements; it is not a general SQL parser or sandbox. The proposal contains one transaction, a proposed PostgreSQL 17 total limit of five minutes and 30-second idle limit, ledger lock/recheck, ordered writer locks before row capture, two-way `EXCEPT ALL` comparison of every prior table's original-column row multiset, empty-new-table/default checks, and seven ledger inserts after preservation. It compares the exact projected ledger before/after and preserves every field of the historical rows captured under lock. The expected transition is **44 active / 45 historical → 51 active / 52 historical**, retaining the rolled-back attempt. Reapplication is a baseline rejection, not a partial-success retry. Unknown commit acknowledgement would require independent identity/ledger/catalog readback, never blind replay.

**Security boundary:** the readback identifies the session/owner but does not establish a provider-supported runtime ACL plan. `securityRequirements` lists the required independently verified identity, roles/memberships/grantors, ownership, effective/default ACLs, RLS/trigger settings, invoker dependencies and retention rules. There is deliberately no catalog/approval flag that unlocks execution. `executableSql` is always null; `reviewSql` raises unconditionally before any lock or DDL, raises again at the missing ACL overlay, and ends in **ROLLBACK, never COMMIT**. Do not remove these guards and run it. A future reviewed operator must implement the actual verified security/catalog assertions and bind backup/rehearsal evidence before offering an executable artifact.

Offline tests cover exact source selection, deterministic hashes, source/evidence/line-ending tampering, missing/extra inputs, hidden/duplicate transaction boundaries, PL/pgSQL preservation, blocked CLI options and transaction/preservation/ledger/rollback ordering. They do **not** execute SQL or prove PostgreSQL parsing, rollback behavior, effective privileges, source-to-live schema equivalence, runtime compatibility or provider identity. The supplied ledger lacks full historical IDs/timestamps/logs; those fields are preserved by the proposed in-transaction snapshot but cannot be pinned to the supplied readback. Complete catalog/sequence/dependency/security preservation, pending-object absence, runtime denial checks, external schema-change fencing, exact backup restoration, serving-commit compatibility and measured lock/temp/WAL/disk/recovery budgets remain required. Partitioned/foreign tables are rejected by the proposal. Failure-injection checkpoint comments identify future rehearsal sites after each source, ACL overlay and ledger write; they are not evidence of rollback testing. Parent S18 validation and production execution remain outside this preparation.
